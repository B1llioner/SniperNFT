# Public mint на сервере

`vinos-genesis-mint` — отдельная команда для **реального public минта Genesis**. Она использует существующую фабрику и детей из `/var/lib/vinos-genesis`; установленный `vinos-genesis-check` остаётся отдельной проверкой signed-минта.

## Запуск одной командой из AWS CloudShell

После установки public-пакета выполни:

```bash
aws ssm start-session --region us-east-2 --target i-0ef42c1e5475d7edb --document-name AWS-StartInteractiveCommand --parameters '{"command":["/usr/local/bin/vinos-genesis-mint"]}'
```

Ключ **любого выбранного кошелька** вводится только в скрытом приглашении внутри открывшегося терминала. Rust определяет адрес из ключа (`--wallet-from-key`) до открытия state; адрес в установленном конфиге не ограничивает этот запуск. NFT получает этот же кошелёк. В команду, аргументы, переменные окружения и файлы ключ не помещай. OpenSea API key не нужен для public-режима.

Для второго кошелька выполни ту же команду в другом терминале и введи его ключ. Оба процесса работают на одном EC2, каждый со своим состоянием, бюджетом, фабрикой и дочерними контрактами. Первый запуск нового кошелька оплачивает подготовку из его баланса. Достаточно ETH на основном кошельке; отдельно пополнять детей не требуется. Повторный одновременный запуск **того же** кошелька блокируется локальным `wallet.lock`.

По умолчанию `setup` использует уже сохранённую фабрику, при необходимости оплачивает создание недостающих детей, затем ждёт public-stage до 48 часов и пытается сминтить до **10 NFT одной транзакцией**, минимум 1. При количестве 1 Rust выбирает прямой минт с кошелька. Проверки состояния и финальная симуляция выполняются перед отправкой; они не резервируют supply и не гарантируют попадание в первый блок. Подтверждённая стоимость предыдущих запусков учитывается в общем бюджете.

Внутри батч-транзакции фабрика проверяет supply перед **каждым** дочерним минтом. При лимите 10 и остатке 3 попытается забрать 3; при остатке 0 завершит цикл. Успехи предыдущих детей сохраняются при обработанных ошибках следующих. Максимум ограничен настройкой количества, подготовленными детьми, условиями минта и газом; превышение денежного лимита останавливает отправку, а не повышает бюджет автоматически.

Включён `watchRpc`: события Genesis/SeaDrop через `wss://robinhood-rpc.publicnode.com` будят проверку условий. Резервные опросы идут с паузой до 10 секунд вдали от старта; без рабочей подписки — до секунды, в последние 30 секунд — 250 мс. Сетевые вызовы увеличивают интервал. Изменённые условия отменяют подготовку, после финальной симуляции условия перечитываются ещё раз. Отправка использует официальный `https://sequencer.mainnet.chain.robinhood.com`; WSS и публичный HTTPS RPC используются для чтения, не заменяют секвенсор.

## Количество и команды

В интерактивной SSM-сессии под `ssm-user`:

```bash
vinos-genesis-mint                  # setup, до 10 NFT
vinos-genesis-mint 1                # прямой минт без создания фабрики
vinos-genesis-mint setup 25         # подготовить недостающих детей и ждать
vinos-genesis-mint start 10         # ждать с уже подготовленной фабрикой
vinos-genesis-mint preflight 0x59Cd658EB1be492c52CcAA2575A90A236F77fAE2 10 # проверки адреса без ключа
vinos-genesis-mint recover 0x59Cd658EB1be492c52CcAA2575A90A236F77fAE2      # проверить сохранённую отправку
vinos-genesis-mint list              # имена запущенных и завершённых сессий
vinos-genesis-mint attach            # вернуться, если сессия только одна
vinos-genesis-mint attach SESSION    # выбрать сессию из list
vinos-genesis-mint reset SESSION     # убрать только завершённую сессию
```

Допустимое количество: 1–100; минимальный результат остаётся 1. Увеличение количества не увеличивает разрешённые денежные лимиты. `start` не создаёт недостающих детей: сначала нужен `setup`. `recover` не создаёт новую транзакцию и не просит ключ. Не удаляй state для повторного запуска: он хранит адрес фабрики, расходы и незавершённые отправки.

Например, одна команда CloudShell для количества 25:

```bash
aws ssm start-session --region us-east-2 --target i-0ef42c1e5475d7edb --document-name AWS-StartInteractiveCommand --parameters '{"command":["/usr/local/bin/vinos-genesis-mint setup 25"]}'
```

## Ожидание переживает разрыв CloudShell

Каждый `setup` и `start` запускает отдельную сессию **tmux** с именем `genesis-mint-<время>-<pid>` на EC2. Имя и команда подключения печатаются до запроса ключа. Нажми `Ctrl+B`, затем `D`, чтобы отсоединиться. Закрытие CloudShell или потеря SSM-соединения не останавливает уже работающий процесс. EC2 должен оставаться включённым; перезагрузка сервера завершит процесс, автоматического перезапуска нет.

Чтобы вернуться к работе, используй `attach`, а не новый `setup`. Когда сессий несколько, `attach` и `reset` требуют конкретное имя; они не выбирают кошелёк за пользователя. После завершения или ошибки вывод остаётся видимым. `reset` откажет, пока выбранный процесс работает. Состояние кошелька и фабрики при этом не удаляется.

Сокет tmux находится в `/var/lib/vinos-genesis/public-mint.tmux` внутри каталога `0700`, доступного `ssm-user`. Приватный ключ живёт в памяти процесса на период ожидания, не выводится и не сохраняется. Сессия запускается с очищенным окружением, без пользовательского tmux-конфига и без core dump.

Логи записываются в `/var/lib/vinos-genesis/4663-<адрес в checksum-регистре>/events.jsonl`; там же сохраняются фабрика, расходы и незавершённая отправка. `wallet` в событиях подтверждает, чей ключ введён. Эти каталоги нельзя менять или удалять ради повторной попытки. Блокировка предотвращает параллельный запуск адреса на этом сервере; между разными серверами она не действует.

## Денежные ограничения

В установленном immutable конфиге:

| Ограничение | ETH |
|---|---:|
| Максимальная разрешённая стоимость одной транзакции | 0.005 |
| Общий лимит подтверждённых расходов этого state | 0.019 |
| Минимальный оставляемый резерв | 0.001 |

Это верхние пределы, а не обещанная фактическая цена. NFT должен быть бесплатным. Лимиты газа и доступного supply проверяются кодом; повышение количества может привести к остановке по бюджету. Проверка отправляющего RPC, восстановление читающего RPC во время ожидания и обновление устаревшей финальной подготовки ограничены тремя попытками. После трёх сбоев подписки бот пишет `drop_watch` со статусом `degraded` и продолжает опросы. Ошибки идентичности контракта завершают процесс сразу. При неопределённом результате отправки сохранённый hash проверяется через `recover`; не создавай отдельный state ради повтора.

Revert тратит комиссию за уже выполненную работу; out-of-gas может израсходовать весь лимит газа транзакции. Даже корректный ранний выход при sold out стоит газ. `status=1` не означает успешный минт: Rust проверяет фактическое число NFT. После подтверждённого revert расходы записываются и процесс останавливается без автоматической повторной отправки. Симуляция снижает риск, но не гарантирует результат при конкуренции.

## Установка reviewed-пакета

Эти шаги выполняет сопровождающий после локальных тестов. Они не запускают mint и не запрашивают ключ.

```bash
node scripts/package-genesis-mint.mjs --output-dir /tmp/vinos-genesis-public-kit-NEW
```

В source-kit входят только allowlisted исходники, контракты, артефакты, lock-файлы и документация. Оба installer-файла перечислены с checksum в `kit-manifest.json`. На Linux x86_64 в CloudShell после сверки checksum:

```bash
bash install-genesis-mint.sh build genesis-mint-source.tgz SOURCE_SHA256
bash install-genesis-mint.sh install /PATH/TO/ARTIFACT.tgz SOURCE_SHA256
bash install-genesis-mint.sh status COMMAND_ID
bash install-genesis-mint.sh verify ARTIFACT_SHA256
bash install-genesis-mint.sh status VERIFY_COMMAND_ID
```

Build использует Rust 1.93.0, `--release --locked`, существующий reviewed toolchain cache. Install проверяет source/binary/config checksum, Linux x86_64, аккаунт, retained instance и закрытый S3 bucket. Artifact публикуется по `/opt/vinos-genesis/<artifact-sha>/`, конфиг `genesis-mint.config.json` принадлежит root. Launcher публикуется атомарно только после проверок и `--help`. При отсутствии `/usr/bin/tmux` installer устанавливает пакет `tmux` через `dnf` и проверяет его запуск.

Для уже проверенной предыдущей public-версии вместо `install` используется `upgrade ARTIFACT.tgz SOURCE_SHA256`: принимаются только закреплённые хеши старой установки. Новый artifact сохраняется отдельно; при живом процессе или активной tmux-pane переключение launcher блокируется. Процесс не останавливается, приватный ключ не читается, state не заменяется. После блокировки сначала изучи сохранённый SSM intent, не повторяй установку вслепую. Уже запущенный процесс не получает обновление автоматически.

Существующие `vinos-genesis-check`, его конфиг и версии не заменяются. `/var/lib/vinos-genesis` и сохранённая фабрика используются повторно. `verify` выполняет только preflight, проверку часов и read-only health-запрос секвенсору. При незавершённом SSM install сначала проверяй сохранённый command ID: автоматической повторной отправки install нет.
