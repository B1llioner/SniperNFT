# Бенчмарк двух транзакций через sequencer

Команда отправляет **реальные транзакции** при наличии `--send`. Один цикл:

1. Разворачивает новый `SequencerBenchmarkNFT` со случайным `runId`.
2. Проверяет receipt, код, владельца и `runId`.
3. Вызывает `mint(quantity)` на этом контракте и проверяет полученные NFT.

Один кошелёк оплачивает обе транзакции и получает тестовые NFT. Общий выпуск не ограничен; контракт допускает повторные минты владельцем. CLI ограничивает один mint значением `quantity` от 1 до 100, контракт — от 1 до 1000. Каждый следующий цикл создаёт новый контракт, поэтому можно отдельно сравнить одинаковые деплои и первые минты. Успешные `N` циклов — это `2 × N` транзакций и `N` контрактов.

Это отдельный ERC-721 для измерений. Его газ и исполнение отличаются от фабрики Rare Friends. В нём нет продажи, расписания, прокси, внешнего контракта минта и функций приёма ETH; `value` в обеих транзакциях равен нулю.

## Первый запуск: ровно две транзакции

После установки зависимостей через `npm ci`, из каталога проекта:

```bash
npm run benchmark:sequencer -- --send
```

По умолчанию: один цикл, один тестовый NFT, официальный sequencer Robinhood, PublicNode для чтений. Нужен ETH в Robinhood Chain и `PRIVATE_KEY` в окружении процесса. Команда проверяет chain ID `4663` и отсутствие уже ожидающих транзакций у кошелька.

Без `--send` можно проверить соединения и симуляцию деплоя:

```bash
npm run benchmark:sequencer -- --from 0xYOUR_WALLET_ADDRESS
```

Этот dry-run ничего не подписывает и не отправляет. Он симулирует только деплой: минт проверяется после появления настоящего тестового контракта в режиме `--send`.

## Ключ на сервере

Для теста используйте отдельный кошелёк. Вводите ключ локально в SSH-терминале со скрытым вводом; он не передаётся аргументом команды и не записывается в JSON-конфиг.

**Bash — обычная оболочка на Linux-сервере:**

```bash
read -r -s -p 'Приватный ключ: ' PRIVATE_KEY
export PRIVATE_KEY
npm run benchmark:sequencer -- --send
unset PRIVATE_KEY
```

**Zsh — например, на macOS:**

```zsh
read -rs 'PRIVATE_KEY?Приватный ключ: '
export PRIVATE_KEY
npm run benchmark:sequencer -- --send
unset PRIVATE_KEY
```

Формат ключа: `0x` и 64 шестнадцатеричных символа. Подпись делается на вашей машине. В sequencer отправляется подписанная транзакция; приватный ключ в RPC, stdout и журнал не попадает.

## Собрать p95/p99

Одна пара проверяет работоспособность. Она даёт по одному наблюдению каждого вида: p50, p95 и p99 в этих строках совпадут.

Для начальной выборки по 100 деплоев и минтов:

```bash
npm run benchmark:sequencer -- --cycles 100 --quantity 1 --send
```

Это до **200 реальных транзакций**. Скрипт остановится раньше, если возникнет ошибка, неопределённый результат, нехватка баланса или общий лимит расходов. Значение `--cycles` не отменяет газовые ограничения.

В конце печатается таблица со столбцами `Kind`, `Phase`, `N`, `p50`, `p95`, `p99`, `max`. Деплой и минт показаны отдельно. Все задержки — в миллисекундах:

| Фаза | Что измеряется |
| --- | --- |
| `prepare` | Проверки RPC, симуляция, оценка газа, получение комиссии, nonce и баланса |
| `sign` | Локальная подпись |
| `submit ACK` | От начала `eth_sendRawTransaction` до ответа sequencer с правильным хешем |
| `receipt observed` | От того же начала отправки до первого обнаруженного receipt через read RPC |
| `total` | Весь цикл одной транзакции, включая подготовку, запись intent, отправку и проверку результата |

Опрос receipt запускается параллельно с ожиданием ACK. Если receipt появился раньше ответа sequencer, метрика это сохранит. Появление receipt включает задержку RPC и опроса; это **не точное время включения в блок и не финальность**. ACK также не является отметкой фактического прихода транзакции внутрь sequencer.

Процентили рассчитываются методом nearest rank только по полученным наблюдениям. Таймауты не превращаются в нули или выдуманные задержки: исходы `failed`, `uncertain`, `reverted` и незавершённые транзакции отражаются отдельно. Receipt откатившейся транзакции учитывается как наблюдение receipt, но не как успешный минт. Если ACK потерялся, а корректный receipt найден, операция может продолжиться: в выборке ACK этого измерения не будет.

При выборке меньше 100 наблюдений выводится пояснение. Даже 100 наблюдений не дают устойчивой оценки редких задержек; сравнивайте серверы с одинаковыми RPC, настройками опроса, количеством NFT и сопоставимым временем запуска.

## Настройки и расходы

Полный шаблон: [sequencer-benchmark.config.example.json](sequencer-benchmark.config.example.json). Это отдельная схема конфигурации, `batch.config.json` для этой команды не используется.

```bash
npm run benchmark:sequencer -- --config sequencer-benchmark.config.example.json --send
```

| Настройка JSON | Флаг | По умолчанию |
| --- | --- | --- |
| `cycles` | `--cycles` | 1, разрешено 1–1000 |
| `quantity` | `--quantity` | 1, разрешено 1–100 |
| `rpcUrl` | `--rpc` | PublicNode Robinhood, только чтения |
| `sequencerUrl` | `--sequencer-url` | Официальный sequencer Robinhood, health и отправка |
| `pollIntervalMs` | `--poll-interval-ms` | 100 мс, пауза между опросами receipt |
| `receiptTimeoutSeconds` | `--receipt-timeout` | 30 секунд на наблюдение receipt |
| `intervalMs` | `--interval-ms` | 250 мс между завершённым циклом и следующим |
| `maxFeeMultiplier` | `--max-fee-multiplier` | 2: множитель base fee, затем прибавляется priority fee |
| `maxGasCostEth` | `--max-gas-cost-eth` | `"0.003"`: максимум резерва на одну транзакцию |
| `maxTotalGasCostEth` | `--max-total-gas-cost-eth` | `"0.01"`: общий бюджет запуска |

Перед каждой подписью проверяется:

```text
уже потраченный газ по receipt + gasLimit × maxFeePerGas <= общий бюджет
```

Также проверяются текущий баланс, лимит одной транзакции и предел Nitro. `gasLimit` включает 20% запаса к оценке RPC. Реальная плата берётся из `gasUsed × effectiveGasPrice` и печатается после каждой транзакции; она не равна автоматически всему выставленному резерву.

Если на кошельке 0.1 ETH и вы хотите разрешить тесту расходовать до 0.08 ETH суммарно:

```bash
npm run benchmark:sequencer -- --cycles 100 --max-total-gas-cost-eth 0.08 --send
```

Это верхняя граница, а не обязательный расход. Цена газа обновляется перед каждой транзакцией. Если бюджет исчерпан после деплоя, минт этого цикла не отправится; уже созданный контракт и его адрес останутся в журнале.

Меньший интервал опроса позволяет раньше заметить receipt, но увеличивает число запросов к read RPC. При стандартных 100 мс один ожидающий receipt требует примерно до 10 запросов в секунду, плюс остальные проверки. Ошибки read RPC считаются отдельно. Сетевой тайм-аут одного RPC-запроса ограничен транспортом 20 секундами; срок наблюдения receipt задаётся отдельно.

## Журнал и остановка

По умолчанию создаётся новый файл `.state/benchmarks/sequencer-*.jsonl` с правами `0600`. Другой путь можно задать через `--output results.jsonl`; существующий файл не перезаписывается. Каждая строка — отдельный JSON: начало запуска, intent до отправки, результат, итоговая статистика.

Перед отправкой хеш, nonce, адрес нового контракта и лимиты газа сохраняются с `fsync`. Приватный ключ, подписанные raw-байты и URL RPC с возможными API-токенами в отчёт не записываются. Хеш также печатается перед сетевой отправкой.

Команда делает **одну попытку отправки каждой транзакции**. Неопределённый результат без receipt останавливает тест: автоматических повторов, замен nonce и отправки следующего цикла нет. Для анализа остаются хеши и частичная статистика. Повторный запуск — новый тест с новыми контрактами; автоматического возобновления журнала нет.

На время запуска удерживается локальный lock кошелька в `.state/benchmarks/`. После обычного завершения или `Ctrl+C` он снимается. После аварийного завершения проверьте PID/host в lock и сохранённые хеши перед удалением оставшейся блокировки. Lock действует для этого бенчмарка на одной машине: тот же кошелёк не следует одновременно использовать в другом отправителе или на другом сервере.

## Проверки реализации

`npm test` проверяет отдельные локальные endpoints для чтений и отправки, nonce, бюджет, ошибки, журнал, раздельное измерение ACK/receipt и арифметику p95/p99.

При наличии Anvil также выполняется полный цикл CLI с настоящим локальным CREATE и минтом: проверяются код, NFT, два receipt и списание газа. Anvil запущен без форка; для совместимости тестовые RPC-прокси моделируют только health sequencer и getter лимита газа Nitro. Это проверка корректности, а не замер скорости mainnet. Если Anvil отсутствует, эти EVM-проверки явно пропускаются; путь к бинарнику задаётся `ANVIL_BIN`.

Пересобрать отдельный тестовый контракт:

```bash
npm run compile:benchmark
```
