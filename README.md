# Минт Rare Friends Genesis

## Несколько NFT с одного кошелька

[`batch.mjs`](batch.mjs) выбирает маршрут по `quantity`: **`1` — прямой публичный минт через SeaDrop; больше `1` — минт через фабрику и новые вспомогательные контракты. Один кошелёк оплачивает газ и по умолчанию получает все NFT.** Количество задаётся в JSON; поддерживается отправка одной и той же подписанной транзакции через несколько RPC с ограниченными повторами.

Порядок запуска, конфиг, dry-run и `--send`: **[BATCH.md](BATCH.md)**. Восстановленный ABI NFT: [Genesis.reconstructed.json](abi/Genesis.reconstructed.json), [точность и ограничения](abi/Genesis.reconstruction.md).

**Запуск заранее и замеры скорости:** [RUNNING.md](RUNNING.md). `npm run batch -- mint --wait ...` заранее проверяет контракт и поддерживает соединения с RPC; `npm run benchmark -- ...` измеряет чтения, симуляцию и локальную подпись без отправки транзакций.

**Деплой и ожидание одной командой:** `npm run launch -- --config batch.config.json --send`. Для уже развёрнутой фабрики: `npm run start -- --config batch.config.json --send`. Фабрика сохраняется отдельно в `.state/`; повторный запуск сначала проверяет сохранённый адрес или незавершённый деплой. Для отправки нужен `PRIVATE_KEY` в окружении. Подробности — в [RUNNING.md](RUNNING.md).

`quantity` задаёт максимум: по умолчанию минтится указанное число либо меньший доступный остаток. Например, запрос 10 при остатке 3 минтит 3. `minQuantity` по умолчанию равен 1; для строго заданного количества задайте его равным `quantity`.

Для всего доступного остатка есть [batch.config.max.example.json](batch.config.max.example.json): `quantity: 1024`, `minQuantity: 1`. Фабрика читает остаток внутри транзакции до создания helper; при 910/1024 выбирает 114, а если конкурент оставит 6 — минтит 6. [Режим гонки и ограничения газа](BATCH.md#забрать-максимум-в-гонке).

## Одиночный минт

Скрипт `mint.mjs` вызывает SeaDrop в **Robinhood Chain Mainnet, chain ID 4663**. Два режима:

- `--public` — публичный минт без подписи, когда открыт публичный этап.
- `--payload mint-payload.json` — `mintSigned`, как в исследованной транзакции; нужна свежая подпись, выданная для вашего кошелька.

По умолчанию выполняются только проверки и симуляция. Для отправки нужен отдельный флаг `--send`.

## Что установлено

По RPC при первоначальном исследовании: публичный этап **15 сентября 2026, 19:00:20–20:00:20 МСК** (16:00:20–17:00:20 UTC), цена 0 ETH, лимит 1 NFT на кошелёк. В момент проверки выпущено 906 NFT. ## Установка

Node.js 18.18 или новее:

```sh
npm ci
npm test
npm run inspect
```

`inspect` разбирает сохранённую транзакцию локально. Он не проверяет, можно ли повторно использовать её подпись.

## Публичный минт

Подставьте свой адрес:

```sh
node mint.mjs --public --from 0xYOUR_WALLET_ADDRESS
```

До открытия этапа скрипт сообщит время его начала. Для отправки после открытия задайте `PRIVATE_KEY` локально. Пример скрытого ввода для **zsh**:

```sh
read -rs 'PRIVATE_KEY?Приватный ключ: '
export PRIVATE_KEY
node mint.mjs --public --send
unset PRIVATE_KEY
```

Ключ вводится в формате `0x` + 64 шестнадцатеричных символа и используется локально для подписи транзакции. Не передавайте его в чате или аргументом командной строки. `--send` отправляет реальную транзакцию в mainnet после успешных проверок.

## Минт Whitelist FCFS с подписью

`mintSigned` проверяет подпись разрешённого сервисного адреса. Она связывает коллекцию, получателя NFT, получателя комиссии, параметры этапа и `salt` в домене EIP-712 SeaDrop этой сети. Подпись можно использовать только один раз. Подпись из исследованной транзакции уже использована и не подходит другому кошельку.

Для своего адреса получите данные транзакции через доступный вам процесс минта OpenSea. Сохраните `from`, `to`, `data`, `value`, `chainId` из подготовленного запроса кошельку в `mint-payload.json`. Если интерфейс кошелька позволяет скопировать calldata, используйте эти данные. Доступность выдачи подписи зависит от допуска вашего адреса к этапу; скрипт не выпускает подписи OpenSea самостоятельно.

Шаблон — [mint-payload.example.json](mint-payload.example.json). В `data` должны быть полные свежие данные `mintSigned`, а не calldata чужой уже выполненной транзакции. `value` задаётся в **wei**. Дополнительные поля газа/nonce из стороннего запроса скрипт не использует.

```sh
node mint.mjs --payload mint-payload.json --inspect
node mint.mjs --payload mint-payload.json --from 0xYOUR_WALLET_ADDRESS
```

После успешной симуляции:

```sh
read -rs 'PRIVATE_KEY?Приватный ключ: '
export PRIVATE_KEY
node mint.mjs --payload mint-payload.json --send
unset PRIVATE_KEY
```

Также поддерживается структурированный JSON с полями `minter`, `feeRecipient`, `quantity`, `mintParams`, `salt`, `signature`; целые числа передавайте строками, чтобы не потерять точность. Подписанные параметры нужно брать целиком из выданного разрешения.

## Ограничения расходов и проверки

- Цена минта по умолчанию ограничена **0 ETH** (`--max-value-eth 0`).
- Верхняя граница `gasLimit × maxFeePerGas` по умолчанию **0.001 ETH** (`--max-gas-cost-eth 0.001`). Это предел, а не прогноз расхода.
- Проверяются сеть, адреса, метод, получатель, срок этапа, лимиты, подпись и её разрешённые параметры, fee recipient, наличие байткода по целевым адресам, `eth_call` и оценка газа.
- Скрипт рассчитан на отправку от кошелька самого получателя NFT. Режим стороннего плательщика не поддерживается.
- В `mint.mjs` нет автоматического ожидания начала минта и повторной отправки. При неопределённом результате отправки сначала проверьте напечатанный хеш транзакции.

Другой RPC можно задать переменной `RPC_URL`. Подключение всё равно должно возвращать chain ID 4663. Справка: `node mint.mjs --help`.

## Исследование и пределы проверки

Промпт для реализации полного теста **пополнение 0.1 ETH → CREATE фабрики → локальное время → минт 10 NFT**, гонки за остаток и быстрой симуляции с виртуальной фабрикой: [FULL_BATCH_SIMULATION.md](prompts/FULL_BATCH_SIMULATION.md). В нём учтена [проверенная поддержка RPC](research/simulate-capabilities.json): `eth_simulateV1` доступен на обычных RPC, `eth_simulateV3` и симуляция через sequencer на проверенных endpoints недоступны. Отдельные тесты гонки реализованы: `npm run test:race` на подготовленном Anvil и `npm run simulate:race -- --target-supply latest` через read-only V1. [Результаты и ограничения](BATCH.md#тест-гонки-за-остаток-114-nft). Команда полного запуска `simulate:full` пока не реализована.

Подробный разбор: [research/ANALYSIS.md](research/ANALYSIS.md), [research/BYTECODE.md](research/BYTECODE.md). Исходные данные, ABI, текущий runtime и снимки RPC сохранены в `research/`.

Проверки `npm test` охватывают кодирование, подпись, ограничения, dry-run, оба маршрута, допустимый меньший остаток, конфигурацию, runtime фабрики, отправку одинаковой транзакции нескольким локальным RPC и receipt. Для `--wait` проверяются ожидание по времени цепочки, смена RPC, отмена и тайм-ауты; отдельно проверяются HTTP keep-alive и бенчмарк. Дополнительно успешны read-only симуляции и локальный fork-тест десяти минтов; подробности в [BATCH.md](BATCH.md).

Исходный Solidity NFT не верифицирован; выводы о нём основаны на текущем байткоде и RPC. SeaDrop верифицирован. Использованный при первоначальном разборе RPC не предоставил runtime на блоке исходной транзакции. Read-only RPC подтвердил, что повтор исходного минта отклоняется, а публичный этап до начала неактивен. Транзакции в mainnet не отправлялись; успешные минты выполнялись только в симуляциях и локальной копии сети.
