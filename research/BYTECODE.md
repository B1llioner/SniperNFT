# Разбор байткода NFT

Контракт: [`0x116eaa62241751e0c98da43d458600c6c17cd361`](https://robin.etherscan.io/token/0x116eaa62241751e0c98da43d458600c6c17cd361#code). Исходный Solidity этого NFT на обозревателе не верифицирован. Ниже — выводы по сохранённому исполняемому байткоду, селекторам, проверенному интерфейсу SeaDrop и логам указанной транзакции. Это разбор пути минта, а не аудит всего контракта.

## Проверенный артефакт

- Файл: [`nft-runtime.hex`](nft-runtime.hex).
- Размер: **17 135 байт**.
- `keccak256`: `0x7117a374c9b7784cd47f550531292764b04aa3a919089c806a79e47852f14b3c` — вычислен локально через `ethers 6.17.0`.
- Байткод содержит полный диспетчер ERC-721/SeaDrop и реализацию минта. Инструкции `DELEGATECALL` нет: это не минимальный прокси, пересылающий вызовы реализации.
- Смещения ниже — позиции инструкций в runtime, в шестнадцатеричном формате. Их можно воспроизвести командой `cast disassemble "$(cat research/nft-runtime.hex)"`.

## Кто может минтить

| Сигнатура | Селектор | Поведение в байткоде |
| --- | --- | --- |
| `mintSeaDrop(address,uint256)` | `0x64869dad` | Диспетчер `0x51c` → тело `0x1027`; проверка вызывающего и минт |
| `getMintStats(address)` | `0x840e15d4` | Чтение счётчиков минта в `0x5ac`–`0x5cd` |
| `totalMinted()` | `0xa2309ff8` | Возвращает счётчик из слота 9 |
| `maxSupply()` | `0xd5abeb01` | Возвращает константу `0x400`, то есть 1024 |
| `updateAllowedSeaDrop(address[])` | `0x60c308b6` | Изменяет разрешённых вызывающих после проверки владельца |
| `getAllowedSeaDrop()` | `0xb2490c3b` | Возвращает массив разрешённых адресов |

`mintSeaDrop` передаёт `CALLER` проверке в `0x235f`. Она читает `mapping(address => bool)` в слоте 13. Если адрес не разрешён, возникает ошибка с селектором `0x15e26ff3`, совпадающим с `OnlyAllowedSeaDrop()`.

Внутренняя функция минта в `0x2701` вызывается из защищённого `mintSeaDrop` через переход в `0x106b`. Селектора обычного `mint(address,uint256)` (`0x40c10f19`) в диспетчере нет. Для исследованного пути скрипт должен обращаться к **SeaDrop**, а SeaDrop уже вызывает NFT. Наличие открытой Solidity-функции `mintSeaDrop` само по себе не разрешает прямой вызов с любого кошелька.

`updateAllowedSeaDrop` переходит в `0xfda`, вызывает проверку владельца в `0x25a0` и обновляет mapping в слоте 13 и массив в слоте 14. Владелец хранится в слоте 8. Список SeaDrop может меняться владельцем.

В начале runtime, `0x05`–`0x0e`, стоит общий запрет ненулевого `CALLVALUE`: нативную оплату для платного минта следует передавать SeaDrop.

## Лимиты и счётчики

`getMintStats(minter)` возвращает:

1. Число токенов, выпущенных этому minter: mapping в слоте 12.
2. Общее **число выпущенных токенов**: слот 9.
3. Максимум: 1024.

В интерфейсе SeaDrop второй результат называется `currentTotalSupply`; в исследованном NFT фактически возвращается `totalMinted`. Его не следует интерпретировать как баланс minter или рассчитывать заново по текущим владельцам. Перевод NFT другому адресу не обнуляет счётчик минта.

Путь в `0x2701` отвергает нулевое количество. В `0x2721`–`0x274f` проверяется `totalMinted + quantity <= 1024`, затем счётчик увеличивается и выпускаются последовательные token ID. `setMaxSupply(uint256)` присутствует, но в `0x1154` требует передать ровно 1024: этим методом изменить встроенный лимит нельзя.

## Создание ERC-6551 аккаунта

Путь операции:

```text
Кошелёк → SeaDrop.mintSigned(...) → NFT.mintSeaDrop(...)
                                  → выпуск NFT
                                  → ERC-6551 registry.createAccount(...)
```

После выпуска каждого NFT в `0x277e` собирается вызов `createAccount(address,bytes32,uint256,address,uint256)`, селектор `0x8a54c52f`. В `0x27fe` выполняется `CALL` к registry `0x000000006551c19487814612e58fe06813775758` с аргументами:

- implementation: `0xED038886c002B285EB0f74971e967B02F6af8ea5`;
- salt: `bytes32(0)`;
- chain ID: инструкция `CHAINID`;
- token contract: `address(this)`;
- token ID: только что выпущенный токен.

Ошибка registry откатывает минт. Указанный implementation относится к создаваемому аккаунту ERC-6551, а не к прокси NFT.

В [исходной транзакции](https://robin.etherscan.io/tx/0x9edd3d788fc164c07d3aaacc2520bfb79ab9b6c1f0a954d5d41523e54ba688fe#eventlog) это подтверждается логами из [`receipt.json`](receipt.json): `Transfer` для token ID **904**, затем `ERC6551AccountCreated` от указанного registry для аккаунта `0x36dCebfC2d374539E78585B8b48C16C0764cf46a`, с теми же implementation, salt, NFT и chain ID **4663**. Следующий лог NFT имеет topic0 `0x558a5655aa2a0708757ea0dd806b3c15047f2b776f927ea8d11d4dd7080ddb47`, token ID и адрес аккаунта; этот topic встроен в код в `0x283f`. Имя этого собственного события без ABI не утверждается.

**Отдельно создавать ERC-6551 аккаунт в скрипте не требуется:** это делает NFT внутри минта.

## Границы выводов

Точный исходник Solidity, его сборка и тесты отсутствуют. Проверка сигнатуры, сроков стадии, цены и разрешённых получателей комиссии находится в SeaDrop и рассматривается отдельно. Настройки владельца и SeaDrop изменяемы; перед отправкой нужна проверка состояния и `eth_call` на используемой сети. Байткод исследован статически, без отправки транзакций.
