# Разбор минта Rare Friends Genesis

Дата исследования: 15 сентября 2026. Область: указанная пользователем транзакция, NFT, его путь минта через SeaDrop, публичное состояние сети и страница коллекции OpenSea. Методы: чтение эксплорера/RPC, локальное декодирование, дизассемблирование, тесты скрипта. Транзакции в mainnet не отправлялись. Последующая проверка прямого и пакетного публичного минта в симуляциях и локальном форке описана в [BATCH.md](../BATCH.md).

## 2. Логи и путь вызова

```text
Кошелёк → SeaDrop.mintSigned
        → NFT.getMintStats
        → проверка этапа, лимитов, платы, fee recipient, подписи
        → NFT.mintSeaDrop
        → ERC6551 Registry.createAccount
```

Логи в receipt:

1. NFT `Transfer(0x0, sender, 904)` — создание NFT №904.
2. Registry `ERC6551AccountCreated`: account `0x36dcebfc2d374539e78585b8b48c16c0764cf46a`, implementation `0xed038886c002b285eb0f74971e967b02f6af8ea5`, salt 0, chainId 4663, NFT №904.
3. Событие NFT с topic0 `0x558a5655aa2a0708757ea0dd806b3c15047f2b776f927ea8d11d4dd7080ddb47`, tokenId 904 и тем же account. Название без верифицированного ABI не утверждается.
4. `SeaDropMint`: minter = payer = sender, quantity = 1, price = 0, feeBps = 1000, stage = 4.

Аккаунт ERC6551 создаётся самим контрактом при минте. Скрипту не требуется отдельная транзакция для него.

## 3. Подпись и право минта

[Верифицированный SeaDrop](https://robin.etherscan.io/address/0x00005ea00ac477b1030ce78506496e8c2de24bf5#code), компилятор 0.8.17. Копия его исходного файла: [SeaDrop.sol](SeaDrop.sol).

Домен EIP-712: name `SeaDrop`, version `1.0`, chainId 4663, verifyingContract = SeaDrop. `SignedMint` включает NFT, **фактического получателя NFT**, feeRecipient, MintParams и salt. `quantity` в подпись не включён, но ограничен проверкой количества и общими лимитами.

Для исходной транзакции локально получены:

```text
digest = 0x177d80653c546eca6a79df4b868a40fbb6b5815d6c16241a44c7993c00845e77
signer = 0xfce4b31128100915f2980bbc3a08894ee5e8f8c3
```

`getSigners` возвращает этот же разрешённый адрес. `getSignedMintValidationParams` задаёт допустимые пределы параметров подписанта. SeaDrop проверяет `_usedDigests[digest]`; подпись используется однократно.

Замена получателя меняет digest и восстановленного подписанта. Для другого получателя нужно новое разрешение. Создать требуемую подпись приватным ключом обычного минтера нельзя: это другой ключ, принадлежащий сервисному подписанту.

На странице OpenSea кнопка **View eligibility** открывает **Connect with OpenSea**. Исследование проводилось в чистом браузере без подключённого кошелька; выдача новой подписи конкретному пользователю не проверялась. API получения подписи не выдумывался и в скрипт не добавлен.

## 4. Контракт NFT и доверенные стороны

NFT имеет собственный runtime 17 135 байт, исходный Solidity не верифицирован. Текущий `eth_getCode` полностью совпал с кодом эксплорера. Подробности и позиции инструкций: [BYTECODE.md](BYTECODE.md).

| Компонент/роль | Ответственность и ограничения |
| --- | --- |
| NFT | Владение ERC721, счётчики minted, фиксированный максимальный выпуск 1024, создание token-bound account |
| SeaDrop | Внешний вход минта, ограничения этапа, одноразовые подписи, платежи |
| Владелец NFT | Настройка разрешённых SeaDrop и параметров дропа; необходимо доверие к его будущим изменениям |
| Подписант | Выдача разрешений signed mint в рамках настроенных пределов |
| Fee recipient | Разрешённый получатель доли платного минта |
| ERC6551 registry/implementation | Создание аккаунта NFT; поведение внешних компонентов полностью не аудировалось |
| RPC | Источник состояния и транспорт отправки; адреса и chain ID проверяются скриптом |

Прямой `NFT.mintSeaDrop` требует разрешённого `msg.sender`. На момент чтения разрешён единственный SeaDrop из таблицы выше. Простого публичного `mint()` для обычного кошелька в исследованном пути нет. В runtime отсутствует `DELEGATECALL`; минимальным прокси он не является. Это не полный аудит всех возможностей контракта.

## 5. Публичный этап и снимок состояния

`getPublicDrop`:

```text
mintPrice = 0
startTime = 1789488020  // 2026-09-15 16:00:20 UTC
endTime = 1789491620    // 2026-09-15 17:00:20 UTC
maxTotalMintableByWallet = 1
feeBps = 1000
restrictFeeRecipients = true
```

Этот режим вызывает `mintPublic(NFT, feeRecipient, address(0), quantity)`. Подпись, salt и allowlist proof ему не нужны. Выполнение возможно только во время активного этапа, при оставшемся выпуске и свободном лимите кошелька.

Блок снимка 63597731: 15 сентября 10:45:30 UTC. `getMintStats` исходного отправителя вернул `(1, 906, 1024)`. Геттеры читались последовательно с `latest`; весь набор не утверждается атомарным снимком одного блока. `totalSupply()` возвращает пустой revert; для ограничений используется `getMintStats`.

## 6. Проверки и неизвестное

- Receipt и calldata получены через RPC и сверены с эксплорером.
- Восстановленная подпись совпала с разрешённым подписантом.
- Повтор точного исходного вызова через read-only `eth_call` отклонён: `MintQuantityExceedsMaxMintedPerWallet(2,1)`. До проверки повторного digest выполнение в этом вызове не дошло.
- Публичный этап ещё не начался во время исследования; успешный публичный минт в сети не выполнялся.
- Исторический `eth_getCode` на блоке исходной транзакции не получен: RPC вернул ошибку отсутствия метаданных. Исторический trace также не получен.
- Отсутствуют оригинальные исходники, тесты и аудит именно NFT. Исследование не заявляет отсутствие уязвимостей.
- Полезные инварианты для скрипта: получатель совпадает с выбранным кошельком; оплата равна quantity × mintPrice; количество не превышает wallet/collection/stage caps; подпись разрешена и не использована; сеть/адрес назначения неизменны.
- Приватный ключ владельца кошелька не читался; код отправки проверяется локально. При изменении состояния между симуляцией и включением транзакция может отклониться.

Сеть подтверждена [официальной документацией Robinhood](https://docs.robinhood.com/chain/connecting/) и [списком сетей Etherscan](https://api.etherscan.io/v2/chainlist). Все сохранённые RPC-ответы имеют публичный характер.
