# Genesis: неизменяемый код и изменяемые настройки

Проверка 16 сентября 2026 года. Область: Genesis NFT `0x116eaa62241751e0c98da43d458600c6c17cd361`, разрешённый SeaDrop `0x00005ea00ac477b1030ce78506496e8c2de24bf5`, Robinhood mainnet, chain ID 4663. Выполнялись чтение исходников/байткода, публичные RPC getters и дополнительный `eth_call` setter без сохранения виртуальных изменений. Ключи и подписи API не использовались; транзакции не отправлялись.

## Проверено на текущем состоянии

Запросы `owner()`, `getAllowedSeaDrop()`, `eth_getCode(NFT)` и `eth_getCode(owner)` привязаны к точному номеру блока каждого RPC:

| RPC | Блок | Время блока UTC |
|---|---:|---|
| `rpc.mainnet.chain.robinhood.com` | 64769298 (`0x3dc4d12`) | 2026-09-16 19:45:50 |
| `robinhood-rpc.publicnode.com` | 64769318 (`0x3dc4d26`) | 2026-09-16 19:45:52 |

Оба RPC вернули:

- Owner: `0x1EcBF27dC1F809179B9ef2d382cd76ccBa21B6d2`; адрес ненулевой, `eth_getCode(owner) = 0x`. Отказ от ownership не подтверждается: getter продолжает возвращать этот адрес. Наличие доступа к его приватному ключу исследование не устанавливает.
- Единственный разрешённый SeaDrop: `0x00005EA00Ac477B1030CE78506496e8C2dE24bf5`.
- NFT runtime hash: `0x7117a374c9b7784cd47f550531292764b04aa3a919089c806a79e47852f14b3c`, совпадает с сохранённым [code.json](code.json) и [разбором байткода](BYTECODE.md).

Эти результаты получены read-only Node RPC-запросами, выведены в журнал инструмента; отдельный сырой файл для этой повторной проверки не создавался. Более ранние полные снимки двух RPC находятся в `.state/opensea-freshness-20260916/`. В них от 14:49:52–53 UTC также подтверждено совпадение SeaDrop runtime с [seadrop-code.json](seadrop-code.json): 21081 байт, hash `0x53e4b9339cf624803c9a7d0195576cca5b917920813508d86b3eb93dcbabeb5c`.

### Дополнительная виртуальная проверка owner-доступа

Сырое ограниченное доказательство: [GENESIS_MUTABILITY_PROBE.json](GENESIS_MUTABILITY_PROBE.json). На каждом RPC использован один зафиксированный блок для сравнения двух вызовов `updateAllowedSeaDrop([])`:

| RPC | Блок | Время блока UTC | `from: owner` | `from: 0x…dEaD` |
|---|---|---|---|---|
| Официальный | `0x3dc79af` | 2026-09-16 20:04:55 | Успех, `0x` | Revert |
| PublicNode | `0x3dc79da` | 2026-09-16 20:05:00 | Успех, `0x` | Revert |

Owner предварительно прочитан с того же блока: `0x1EcBF27dC1F809179B9ef2d382cd76ccBa21B6d2`. У owner и постороннего тестового адреса нет кода. Revert имеет selector `0x118cdaa7`, совпадающий с вычисленным `OwnableUnauthorizedAccount(address)`, и аргумент адреса `0x…dEaD`. NFT runtime hash остаётся прежним.

Это `eth_call`, а не подписанная или отправленная транзакция: поле `from` задаёт виртуального вызывающего и не требует ключа. Проверка показывает, что конкретный вызов setter от текущего owner проходит, а от постороннего адреса отклоняется. После каждого сравнения реальный `getAllowedSeaDrop()` на исходном блоке и новом latest-блоке вернул прежний единственный SeaDrop. Виртуальный результат storage внутри вызова отдельно не читался; последовательная `eth_simulate` не выполнялась. Никаких новых прав и изменений реального списка эти проверки не создали.

## Связь NFT → SeaDrop можно изменить

Сохранённый и повторно сверенный NFT runtime содержит `updateAllowedSeaDrop(address[])`, selector `0x60c308b6`. Диспетчер: `PUSH4 60c308b6` на PC `0x20d`, переход к wrapper `0x04f6`. Проверенный ранее путь тела `0x0fda` вызывает проверку owner в `0x25a0`, затем меняет разрешения в mapping слота 13 и массиве слота 14. Owner хранится в слоте 8. Смещения и механизм описаны в [BYTECODE.md](BYTECODE.md).

Следовательно, текущий ненулевой owner имеет предусмотренный байткодом путь изменения разрешённого списка SeaDrop. Это изменение storage NFT по прежнему адресу. Утверждение «NFT навсегда связан только с этим SeaDrop» не соответствует исследованному runtime.

Для вызова `mintSeaDrop` NFT проверяет **вызывающий адрес** по этому списку. Замена списка может прекратить работу старого маршрута минта. Наши скрипты не принимают новый адрес автоматически: требуется заранее одобренный маршрут с проверенным code hash.

## Настройки минта меняются без замены кода

В диспетчере Genesis найдены также:

| Интерфейс NFT | Selector |
|---|---|
| `updatePublicDrop(address,(uint80,uint48,uint48,uint16,uint16,bool))` | `0x1b73593c` |
| `updateSignedMintValidationParams(address,address,(uint80,uint24,uint40,uint40,uint40,uint16,uint16))` | `0x511aa644` |
| `updateAllowList(address,(bytes32,string[],string))` | `0x3680620d` |
| `updateAllowedFeeRecipient(address,address,bool)` | `0x48a4c101` |

Наличие этих selector проверено непосредственно в NFT runtime. Точный Solidity исходник Genesis не верифицирован, поэтому таблица не заменяет полный анализ всех ветвей этих методов.

В [официальной реализации ERC721SeaDrop](https://github.com/ProjectOpenSea/seadrop/blob/main/src/ERC721SeaDrop.sol) аналогичные wrappers проверяют owner/self и разрешённый SeaDrop, затем вызывают setter SeaDrop. Это подтверждение интерфейса и архитектуры; официальный базовый исходник нельзя выдавать за точную сборку Genesis.

В [верифицированном SeaDrop](https://robin.etherscan.io/address/0x00005ea00ac477b1030ce78506496e8c2de24bf5#code), сохранённом как [SeaDrop.sol](SeaDrop.sol), public-stage, allowlist root, разрешения fee recipient/payer и правила signer хранятся отдельно для каждого NFT. Setter работает с записью `msg.sender`, проверяя NFT-интерфейс вызывающего. Посторонний EOA не получает возможность переписать настройки Genesis, просто указав его адрес. [Официальный исходник SeaDrop](https://github.com/ProjectOpenSea/seadrop/blob/main/src/SeaDrop.sol) также показывает добавление/удаление signers через ограничения signed mint; нулевой `maxMaxTotalMintableByWallet` удаляет signer.

Public mint использует актуальные onchain параметры и не требует backend-подписи. Signed mint зависит от minter, NFT, SeaDrop/chain domain, fee recipient, параметров, salt, срока и действующих правил signer. Выдача новой backend-подписи сама по себе не отзывает другую действительную подпись; отзыв signer или изменение его допустимых диапазонов может сделать старую подпись непригодной.

## Код не является обычным upgradeable proxy

Повторный локальный разбор обоих runtime с пропуском данных `PUSH1..PUSH32` не нашёл исполняемых инструкций `DELEGATECALL`, `CALLCODE` или `SELFDESTRUCT`. У NFT 17135 байт полноценной реализации. У SeaDrop проверена последовательность инструкций до 53-байтового хвоста metadata. У NFT завершающие два байта не задают корректную длину CBOR metadata, поэтому произвольный хвост не отрезался.

В исследованных runtime нет пути обычного proxy upgrade через `DELEGATECALL`. Это не означает неизменность storage, разрешений или внешних зависимостей. Создаваемый во время минта ERC-6551 account имеет отдельный implementation: этот адрес не является implementation прокси самого Genesis NFT; см. [BYTECODE.md](BYTECODE.md).

## Практический вывод и границы

Нужно контролировать одновременно code hash, список разрешённых SeaDrop, public-stage, supply и используемые правила signer. WSS-события служат сигналом перечитать RPC; сами события не разрешают отправку. Финальная симуляция и последующая проверка параметров ограничивают окно устаревания, но не резервируют supply и не запрещают owner изменить настройки после последнего чтения, до включения транзакции.

Это исследование конкретных путей и текущего ownership, а не полный аудит Genesis. Не установлены точная исходная сборка NFT, доступность ключа owner и неизменность всех внешних контрактов ERC-6551. Во время текущего повторного чтения обозреватель отвечал 403; выводы по runtime опираются на RPC и ранее сохранённые артефакты, а не на доступность страницы обозревателя.
