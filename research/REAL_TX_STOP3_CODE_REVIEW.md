## Проверенные границы политики

- **Три подтверждённые неудачи подряд:** `State::record` классифицирует последовательный префикс раундов, независимо от порядка поступления receipts. Успех сбрасывает счётчик. После третьей неудачи `THREE_CONSECUTIVE_FAILURES` фиксируется необратимо.
- **`first-block`, по умолчанию:** успех требует всей партии и первого L2-блока целевой секунды. Монитор сверяет hash receipt с заголовком, а для полной партии — связанного непосредственного предшественника с меньшим timestamp. Частичная партия не проходит количественный критерий; непроверенный факт промаха по блоку не выдумывается.
- **`no-mint`:** любой положительный фактический минт считается успехом политики. Нулевой минт и подтверждённый revert считаются неудачами. Поздний полный минт не накапливает неудачи.
- **Обратная связь:** до следующего send проверяется `sentRounds - evaluatedPrefix >= 3`. Это три отправленных раунда сверх полностью классифицированного префикса; более поздние известные результаты могут оставаться за неизвестным ранним раундом. Отдельный `FEEDBACK_LAG` не выдаётся за три доказанных неудачных минта.
- **Неоднозначность:** timeout, потерянный ACK или неправильный hash прекращают дальнейшие отправки после обнаружения; автоматического resend нет. Ошибки наблюдения не превращаются в нулевой минт. Pending-маркер блокирует перезапуск с новым output. Остановленная HTTPS-серия не переходит к WSS-деплою.

Остановка проверяется перед новой отправкой и не отменяет уже принятые транзакции. Задержка получения подтверждений учитывается отдельным ограничением обратной связи.

## Путь отправки и сохранность доказательств

Подписи и durable intents готовятся до начала окон. Цикл использует локальный snapshot монитора, проверки времени, регистрацию hash и переиспользуемый sender. Receipt/header RPC для классификации выполняются отдельной задачей `RoundMonitor`; цикл отправки их не ожидает. Snapshot-stop не снимается более поздними результатами; неизвестные исходы имеют `minted: null`. Задачи принадлежат вызывающему объекту и отменяются при его уничтожении, включая отмену `finish`.

ACK и запись журнала остаются последовательными операциями. Если их задержка вывела следующий раунд за границу его секунды, CLI останавливается, сохраняя последовательность nonce.

Причина stop сначала сохраняется в журнале. После сбора наблюдений preliminary-файл записывается до дополнительного анализа блоков и `ownerOf`. Подробный файл создаётся отдельно после успешных чтений. Раннее прерывание может оставить только журнал и pending-маркер.

## Результаты тестов

Локальная среда: Anvil 1.7.1 без fork, chain ID 4663, блоки 0.2 s, синтетический ключ, отдельные loopback HTTP/WS маршруты. Это не проверка TLS или задержек Robinhood.

| Сценарий | Подтверждённый результат |
| --- | --- |
| Полный EVM-файл | **10/10 passed**, без пропусков, около 184 s. Базовая both-серия: 26 tx, по 10 полных батчей и 10 first-block hits на маршрут. |
| Default first-block, offset 700 ms | Ровно 6 tx: три setup и три поздних батча по 10 NFT. First-block hits: 0. WSS не развёрнут, pending сохранён. |
| No-mint, offset 700 ms | Все 13 tx/100 NFT; first-block hits: 0, exit 2, pending снят. |
| No-mint, реальное время EVM +2 s перед mint | Ровно 6 tx; три успешных receipts с `Expired`, minted=0; WSS не развёрнут, pending сохранён. |
| Финальный повтор трёх затронутых сценариев | **3/3 passed**, без пропусков, около 89 s; проверены разные diagnostic-файлы и подробные findings. |

Полный прогон начался до двух диагностических исправлений. После них все три затронутых сценария повторены на исправленном debug-бинарнике с усиленными assertions. Остальные проверки покрывают preflight без отправки, бюджет, неверный ключ, внешний nonce, timeout до принятия и потерянный ACK после принятия, включая запрет перезапуска через новый output.

```bash
ANVIL_BIN=/path/to/anvil node --test test/rust-timed-mint-evm.test.mjs
ANVIL_BIN=/path/to/anvil node --test --test-name-pattern='failure guard|failure policy' test/rust-timed-mint-evm.test.mjs
```

Для нестандартного расположения бинарника задаётся `RUST_MINT_BENCHMARK_BIN`; по умолчанию используется `rust-mint-benchmark/target/debug/rust-mint-benchmark`.

## Остаточные ограничения

- Локальный результат не предсказывает попадания в mainnet при конкуренции. RPC предоставляет незавершённый snapshot; поздняя реорганизация может изменить включение. Финальность не доказана.
- Observer делает один запрос раз в 100 ms; десять pending hashes дают около секунды на повторный опрос плюс сеть. Медленный reader способен вызвать консервативный `FEEDBACK_LAG` при уже сминченных NFT.
- При неразрешённых receipts `gasCostWei` содержит только известные расходы. Неизвестный receipt не означает нулевую комиссию; верхняя подписанная граница бюджета проверяется отдельно.
- Lock/pending действуют для общего каталога на одном сервере; внешние приложения и другие машины могут расходовать баланс и nonce.
- N=10 не даёт устойчивой оценки p95/p99. Проверка конкретного snapshot не является формальным доказательством отсутствия всех ошибок.
