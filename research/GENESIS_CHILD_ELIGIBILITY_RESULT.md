## Вывод

Фабрика переиспользована, оба ребёнка созданы и подтверждены на сети. OpenSea не выдал mint payload; симуляция NFT-минта и его отправка не выполнялись. Дополнительная проверка API без приватника выявила в ответах обоим детям причину недостаточного баланса. Это не подтверждение запрета контрактов и не гарантия допуска после пополнения.

Серверный CLI и контракты при разборе не изменялись. Диагностика использовала публичные RPC-чтения и максимум три вызова документированного API построения транзакции; blockchain-транзакций не было.

## Что означал отказ OpenSea

В `rust-genesis-minter/src/opensea.rs` тело ошибки отбрасывается, HTTP 422 преобразуется в общий `ApiError::NotEligible`. Поэтому фраза `balance, eligibility, limit or supply` в CLI не выбирает конкретную причину. [Документация метода](https://docs.opensea.io/reference/build_drop_mint_transaction) действительно перечисляет эти разные предпосылки под одним статусом.

Для уточнения выполнен отдельный ограниченный probe: один временный API-ключ в памяти, три запроса построения payload для основного кошелька и обоих детей. Приватник не нужен, данные в сеть блокчейна не отправляются. Ключ, сырые ошибки и calldata не сохранялись; строки ошибок классифицировались в памяти по фиксированным категориям.

| Адрес | HTTP | Выделенные категории ответа | Payload |
| --- | --- | --- | --- |
| Основной кошелёк | 422 | not_eligible, stage_inactive | Нет |
| Child 0 | 422 | insufficient_balance | Нет |
| Child 1 | 422 | insufficient_balance | Нет |

Категории — результат анализа текста, не дословные машинные коды сервера. Они получены в повторной проверке; исходные сырые ответы первого запуска не сохранились. Оба child-ответа имели одинаковый SHA256. Результат достаточен, чтобы связать текущий отказ детям с нулевым балансом minter, но порог требуемого баланса не установлен. Отказ основному кошельку показывает, что наличие ETH само по себе не гарантирует допуск к текущему этапу.

## Этапы и дальнейший маршрут

[Страница коллекции OpenSea](https://opensea.io/collection/rare-friends-genesis/overview) на момент проверки показывала активный Whitelist FCFS, тип Allowlist, бесплатный минт и лимит 1 на адрес. Public указан отдельным этапом. Сохранённый onchain public window: 17 сентября 2026, 17:00:20–18:00:20 МСК (`1789653620..1789657220`). Эти параметры и остаток необходимо заново прочитать перед исполнением.

Для signed-маршрута нужны действительные разрешения именно детям. Пополнение не доказывает их членство в allowlist. Текущие дети предназначены для бесплатного минта: в контракте нет payable receive/fallback или функции вывода ETH; инструкции переводить им ETH не давались и баланс не изменялся.

Для публичного этапа `mintPublic` в [SeaDrop](https://github.com/ProjectOpenSea/seadrop/blob/main/src/SeaDrop.sol#L170) не принимает подпись OpenSea. Существующий Rust `mode: public` умеет построить этот вызов локально, сохранив проверки окна, runtime, лимитов и симуляцию. Дети с нулевым ETH могут участвовать в бесплатном внутреннем вызове: внешний газ оплачивает основной EOA. Это следует из схемы вызовов; успех двух настоящих публичных минтов на текущем состоянии ещё не проверен, а публичный этап пока не активен.
